1. 比对方法

本次盘点严格从源码出发，先锁定官方上游，再做当前仓库工作树与上游源码树的对照，不使用“基于文档猜测功能范围”的方法。

  • 官方上游基线：upstream/main @ 96c2526f2aed0cf80c81aec11269e35b8cb956c8

  • 结论：必须按“当前源码树 vs 官方源码树”做逐文件、逐功能族盘点

4. 当前迁移动作矩阵

这一节不再列“脏工作树里还有什么文件”，而是直接回答迁移时最关键的问题：哪些基础胶水建议优先搬，哪些能力按需搬，哪些实验线已经明确不要再迁回新版。

4.1 建议优先迁移

  • 终端路径持久化 / cwd 胶水：这是当前最值得搬的基础层修复，解决“从当前终端继续打开动作时掉回用户目录”的老问题。主代码：frontend/util/launchcwd.ts、frontend/app/view/term/termwrap.ts、frontend/app/view/term/term-settings-menu.ts。
  • PVE / Remote GUI 主线：如果新版还要保留服务器 GUI、VNC、PVE 自动登录，这一整条主线必须整体迁。主代码：emain/pve-auth.ts、frontend/app/workspace/servers-refresh.ts、frontend/app/view/pvevnc/pvevnc.tsx、schema/connections.json。
  • 中文化 / i18n 主线：这不是简单文案替换，前后端初始化、资源文件、文档和扫描脚本都要一起看。主代码：frontend/app/i18n.ts、locales/、public/locales/、i18n-scan-visible.cjs、README.md。
  • 隔离开发实例链：后面继续迁移和验证时，dev:linked 这套思路本身建议保留。主代码：scripts/dev-instance.ps1、package.json 里的 dev:linked 相关脚本。

4.2 按产品取舍决定是否迁移

  • 终端语音自动播报 / TTS：如果新版还保留语音链，至少要把 terminal-speech.ts 的 freshness 修复和主进程 TTS IPC 一起迁；如果不保留语音，这整条可整体切掉。
  • Workbench / Codex resume / 顶部 Codex / Claude 按钮：这三块互相缠着，且现在按钮语义已经改成“只在当前终端注入命令”。如果新版不要这套 agent 工作流，就不要只迁 UI 壳。
  • Explorer 风格目录视图 / 收藏夹：如果新版要继续做增强文件管理，这块值得迁；如果只保留原生文件预览，可按单元整体删。
  • WaveAI backend 扩展：reasoning effort、verbosity、额外 token 字段和调试日志只在你继续保留这套 OpenAI / Responses API 扩展时才值得迁。

4.3 已明确不要回迁的线

  • 外部 recommended browser 预热链：不要把外部 Chrome 预热、推荐浏览器 IPC 这条实验链再带回新版。
  • 布局 / 多分屏侧栏面板 + 右侧重复 Resume 图标：底层布局能力可以留，旧的侧栏面板和右侧重复入口不要回迁。
  • git 侧栏快捷入口：当前已经整条删除，迁移时不要因为旧报告里出现过 GitPanel 就顺手恢复。
  • “用指定 AI 打开”里的 AMP / IFlow：当前菜单项已经删掉，迁新版不要再加回来。
  • Beta Browser / OpenVSCode 实验支撑脚本：scripts/openvscode-clean.ps1、scripts/seed-dev-workbench.ps1、以及相关左侧入口都属于已回收实验线。
