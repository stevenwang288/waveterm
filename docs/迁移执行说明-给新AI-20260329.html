4. 开发版怎么启动，才不会顶掉正式版

主题 必须做法 原因 / 证据
标准入口 npm run dev:linked
npm run dev:linked:status
npm run dev:linked:stop		 仓库规则要求前端 / Electron / 终端交互改动走隔离实例验证，不要把正式安装版当测试环境。
首启 / 冷状态验证 powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/dev-instance.ps1 -Action start -FreshState 只有这种情况才该 fresh。不要把 fresh 变成默认日常开发行为。
为什么不会顶掉正式版 开发版状态写入：
.tmp/dev-linked/current/config
.tmp/dev-linked/current/data
.tmp/dev-linked/current/electron-userdata
并显式设置：
WAVETERM_CONFIG_HOME
WAVETERM_DATA_HOME
WAVETERM_ELECTRON_USER_DATA_HOME		 隔离开发版和正式安装版不共享同一套用户数据目录。真正危险的是绕开脚本自己启动、或一次开多个实例。

5. 开发版怎么测试

  1. 改了前端后先执行 npm run build:dev。
  2. 只要碰了 Go / starter layout / schema / backend 启动链，再执行 npm run build:backend:windows。
  3. 停旧实例：npm run dev:linked:stop。
  4. 需要冷状态验证时，用 scripts/dev-instance.ps1 -Action start -FreshState。
  5. 检查状态：npm run dev:linked:status。
  6. 检查 dev.log 至少出现 Init Bare、Init Wave imported App、Wave First Render Done。
  7. 最终必须看真实窗口，而不是只看日志。
最大坑点：npm run build:dev 不会重打 Go 后端 wavesrv。如果你动过 pkg/** 或 starter layout，却没跑 npm run build:backend:windows，最后看到的很可能还是旧界面。

6. 安装包应该怎么打

主题 规则 结果
标准打包入口 npm run release:win
dirty 工作树才用 npm run release:win:allow-dirty		 scripts/release-win.ps1 会先做构建/打包，再处理安装包复制。
脚本默认桌面目录 DeskDir = "D:\\DeSK" 安装包会自动复制一份到 D:\DeSK，不需要另写复制脚本。
产物路径 主包：make/<version>/WAVE-win32-x64-<version>.exe 桌面副本：D:\DeSK\WAVE-win32-x64-<version>-fix-<sha>.exe
打包前顺序 如果碰了 Go / backend / schema：
npm run build:prod
npm run build:backend:windows
npm run release:win		 避免前端是新的、安装包里的 wavesrv 还是旧的，最终产出半新半旧安装包。

8. 推荐执行顺序

  1. 先拉最新上游并锁定基线 commit。
  2. 先读总盘点、当前任务进展、本文。
  3. 先删不要迁的线：Goose / DeerFlow / promptoptimizer 默认入口线、Beta Browser / OpenVSCode 实验线。
  4. 再迁基础胶水：launchcwd.ts、favorites-model.ts、term-settings-menu.ts、dev-instance.ps1。
  5. 再迁保留功能：顶部 Claude / Codex、TTS、PVE / Remote GUI、汉化。
  6. 前端后跑 npm run build:dev，Go/backend 后跑 npm run build:backend:windows。
  7. 用隔离实例做真实验证。
  8. 最后再打包：npm run release:win。

9. 最低交付检查清单

  1. 新版默认启动不再进入 Goose / DeerFlow / promptoptimizer。
  2. 隔离开发版能正常启动，且不污染正式版数据。
  3. 只保留一个隔离开发实例。
  4. 涉及 Go 后端时，已执行 npm run build:backend:windows。
  5. 真实窗口已验证，不是只看日志。
  6. 主安装包存在于 make/<version>/WAVE-win32-x64-<version>.exe。
  7. 桌面副本存在于 D:\DeSK\WAVE-win32-x64-<version>-fix-<sha>.exe。
  8. 控制台已输出最终 sha256。
